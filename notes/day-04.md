## 概念整理與易混淆點

- Schema可以指結構定義；PostgreSQL的schema也指收納資料表的命名空間，多張表可共用public。
- Migration是事先準備的變更指令，不是執行後產生的log。001／002是順序編號，不是資料編號；工具可一次執行全部待套用變更。
- 已套用的migration通常新增下一份修正；長期專案可建立baseline，但既有環境需要對齊紀錄，不能直接重跑建表。
- 收緊欄位限制前，先控制新輸入，再處理舊資料，最後加約束；舊資料的處理方式由業務需求決定。
- 交易提供相關修改的原子性，不自動消除所有競態。庫存條件式更新與交易是概念預習，未做實驗。
- 連線池閒置連線仍占資源，保留與關閉是延遲和資源的取捨；30秒是目前設定，不是通用最佳值。
- 前端依error.code處理行為，文案可集中管理。測試可共用部分定義，但不能只照讀實作設定而失去獨立需求驗證。
- fetch收到400／500仍可能正常取得回應，要檢查status／ok；204沒有內容，不應直接解析JSON。
- 刪除後refetch列表是合理做法；刪除成功但列表刷新失敗，要區分錯誤階段。
- 前端競態是過時回應覆蓋畫面，後端競態可來自多使用者同時修改。Loading、停用操作與忽略舊回應各有用途。
- Integration test（整合測試）實際呼叫服務並檢查契約；fixture（測試基礎資料）讓起始狀態可預期。

## 1. Schema（結構定義）與 Migration（結構遷移）

**一句話結論：Schema 是資料表長什麼樣子的設計圖，Migration 是把資料庫從一個版本改到下一個版本的施工單。**

Schema 說明有哪些資料表、每張表有哪些欄位、欄位的型別與限制。你的 `users` 和 `expenses` 就是兩張表的 schema。

筆記裡有個容易混淆的點：PostgreSQL 的 schema 這個詞還有第二個意思，是「收納資料表的命名空間」，預設叫 `public`。看到 schema 時，先判斷它是指「設計圖」還是「資料夾」，多數時候是前者。

Migration 的重點是**順序**與**可重現**。你現在有 `schema.sql`，它只能在空資料庫建出最新版本。但如果資料庫已經有資料，要加一個欄位就不能重跑建表，因為會把資料蓋掉。所以要寫成 `001`、`002` 這樣的施工單，一份一份依序套用。前端的類比是 Git 的提交歷史：每次改動留一筆，任何人從頭套一遍都得到同樣結果。你目前還沒有 migration 工具，這是 W2 要做的。

## 2. Connection Pool（連線池）

**一句話結論：連線池是預先開好的一批資料庫連線，要用時借、用完還，不用每次重新建立。**

跟前端的類比：每次請求都重新跟資料庫握手，成本高。連線池像計程車排班，車先排好，客人來就上車、下車後車子回去排隊。

要記的兩件事：

- **借了要還。** 如果某段程式借了連線卻因為錯誤沒還，池子的連線會慢慢被借光，之後的請求全部卡住，這叫連線洩漏。所以程式裡會用 `finally` 保證一定歸還。
- **閒置連線也占資源。** 池子保留多久、最多開幾條，是延遲與資源的取捨，你目前的 30 秒只是設定值，不是標準答案。

## 3. Transaction（交易）

**一句話結論：交易是把好幾個資料庫修改綁成「全部成功或全部撤銷」的一包。**

經典例子是轉帳：從 A 扣 100、對 B 加 100。如果扣完 A 之後系統當掉，沒有交易的話 A 少了錢、B 沒收到。有交易的話，中途失敗會 rollback（回滾）全部撤銷，兩個都沒動。成功才 commit（提交）。

一個重要的限制，筆記也有寫：**交易不會自動解決所有同時操作的問題。** 兩個人同時改同一筆資料，還需要其他機制，這是 W4 的版本衝突和冪等鍵。現在先記住交易管的是「一包操作要不要一起生效」。

你目前**還沒實作過交易**，筆記標的是 L1（只討論過），W4 才會實際做。

## 這幾個縮寫

SQL（Structured Query Language，結構化查詢語言）。PK（Primary Key，主鍵）是一張表裡唯一標識每一列的欄位。FK（Foreign Key，外鍵）是指向另一張表主鍵的欄位，用來維持兩張表的關聯。CRUD（Create, Read, Update, Delete，新增、讀取、更新、刪除）是資料操作的四個基本動作。
