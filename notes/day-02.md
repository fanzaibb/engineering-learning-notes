# Day 02｜從路由與 ARP 到 Azure 虛擬網路

**日期** 2026-11-06

## 已實作｜在 macOS 追蹤封包的第一站

- 用 `route -n get default` 查到預設閘道，再用 `route -n get 8.8.8.8` 確認到這個目的地也走同一個閘道。
- 用 `arp -n 192.168.0.1` 查到閘道在本機 ARP 表中已有一筆 MAC 位址對應。ARP（Address Resolution Protocol，位址解析協定）能在本地鏈路上由下一站的 IPv4（Internet Protocol version 4，網際網路協定第 4 版）位址找到其 MAC（Media Access Control，媒體存取控制）位址。
- 用 `traceroute -n -m 3 -q 1 8.8.8.8` 探測前三跳，確認第一跳就是預設閘道。三個探測封包的 TTL（Time to Live，存活時間）分別設為 1、2、3。畫面上的毫秒數是本機到該次回覆的往返時間。輸出顯示探測封包長度為 40 位元組，此例的格式是 20 位元組 IPv4 標頭、8 位元組 UDP（User Datagram Protocol，使用者資料報協定）標頭及 12 位元組探測資料。

封包的目的位址是 `8.8.8.8`。路由表選出第一站，ARP 表提供這一段傳送所需的目的 MAC 位址。

## 已練習｜子網路與路由選擇

- `0.0.0.0/0` 匹配所有 IPv4 位址，`/32` 只匹配單一位址。多條路由同時匹配時，選擇前綴最長的路由。
- IPv4 位址共 32 位元。每多固定一個前綴位元，位址範圍就減半。`/24` 有 256 個位址，`/25` 有 128 個，`/26` 有 64 個。
- 在 `10.0.1.0/24` 中，`.20` 和 `.150` 分別落在兩個 `/25`，連線會跨子網路。路由決定怎麼送，安全性規則決定是否允許通過。

## 已實作｜建立 Azure 網路與兩個子網路

用 Azure CLI（Command-Line Interface，命令列介面）在 `southeastasia` 建立 `rg-learning-day02` 和 VNet（Virtual Network，虛擬網路）`vnet-day02`，位址範圍為 `10.0.1.0/24`。第一次建立時，Azure 自動註冊了訂閱中的 `Microsoft.Network` 資源提供者。

| 子網路 | 位址範圍 | 驗證結果 |
|---|---|---|
| `subnet-app` | `10.0.1.0/25` | `Succeeded` |
| `subnet-db` | `10.0.1.128/25` | `Succeeded` |

用 `az network vnet subnet list` 確認兩個子網路。實驗後已清理資源群組。

## 已討論｜網路門禁與排查

- NSG（Network Security Group，網路安全性群組）依優先順序檢查，數字小的先看，第一條符合的規則決定結果。練習先允許 `10.0.1.0/25` 連到 `10.0.1.150:5432`，再拒絕其他來源連到同一目的地。已放行連線的回程由狀態追蹤處理。
- 連線逾時、連線被拒絕、資料庫密碼錯誤是不同的排查線索。依情況檢查路由與門禁、服務是否監聽，以及後端實際載入的帳密。
- VPN（Virtual Private Network，虛擬私人網路）可以提供進入公司測試網路的路徑。CORS（Cross-Origin Resource Sharing，跨來源資源共享）控制瀏覽器是否讓網頁讀取跨來源回應。Postman 桌面版打得通，只驗證了該次請求能到達後端並取得回應。私人資料仍由後端檢查身分和權限。

## 延伸討論｜部署與相容性

- 更換資料庫帳密後，舊連線可能仍能查詢。部署驗證應包含建立新連線及實際查詢，因為僅檢查程序存活的 `/health` 無法驗證資料庫連線。
- 將記帳金額從 `amount` 過渡到 `amount_cents` 時，先增加欄位並補齊舊資料，過渡期維持新舊讀寫相容。請求同時帶兩欄且金額不一致時回傳 `400 Bad Request`，避免存入有歧義的值。
- 前端先上傳新版程式檔，再發布指向新檔的 `index.html`。保留舊檔一段時間，讓仍開著的舊分頁可以載入延遲下載的檔案。切換驗證包含從舊分頁新增，再用新分頁讀回。

## 待上機驗證

在 Azure 套用 NSG 規則，分別用符合及不符合來源條件的連線驗證放行與拒絕。今天只建立虛擬網路與子網路，門禁仍停留在紙上練習。
