## 技術與專案範圍

- 延續現有 expense-api，使用 Node.js、TypeScript、PostgreSQL 與 pg 驅動程式。先用 SQL（Structured Query Language，結構化查詢語言）理解資料模型與交易。
- 第二週選定一套服務端框架，預設候選為 Express。以既有端點與測試行為為基準，框架導入控制在 2 小時內，選型理由記入當堂紀錄。
- 前端沿用使用者熟悉的 Vue 或 React，在既有能力上建一個精簡記帳介面。第一週選定後固定。預設 Vue，避免重新教授整套前端框架。
- 本機以 OrbStack 管理 PostgreSQL 容器，明確分開映像、容器與持久化資料卷。遇到環境阻礙依替代方案處理。
- 專案採單一後端，採用一條完整部署路線，預設 Azure App Service 容器搭配 Azure Database for PostgreSQL。若訂閱、區域或費用不適合，在實驗前選定替代並記錄。其他 AZ-104 考點另用短期實驗覆蓋。
- AI（Artificial Intelligence，人工智慧）agent 開發協作從W1起融入既有任務，專項訓練共6小時，計入各週後端時數。使用者負責需求、設計判斷、程式審查與驗收。
- 產品內的AI分類建議移入後續選修，這次六小時用於agent開發流程。
- MySQL 改寫、微服務、Kubernetes、分散式交易、進階效能調校、大型檢索與多代理產品開發列入後續課程。

## 後續主線｜開源產品架構與重建

使用者於2026-11-09指定，基本概念與核心實作完成後，希望以GitHub上有實際原始碼的開源產品，進行一次從架構研究到功能實作的完整學習。產品待共同選定，範圍確定後再編列時數。此主線列為進階階段，本版八週240小時仍按現有核心成果驗收。

選材優先考慮具明確授權、可固定版本、可在本機重建、前後端與資料流程有足夠可讀程式的產品。先檢查倉庫是否真的包含要學的功能，以及建置維護狀態、外部服務依賴和執行成本，再決定實作範圍。大型公司的公開函式庫、範例或架構文章依其實際內容使用，避免把局部程式推定成完整產品實作。

教學依序進行需求與主要使用情境、系統全貌、功能的端到端資料流、資料模型與狀態、服務邊界、實作及驗證。先選一條垂直功能，例如發布內容與列表、商品與下單，從介面一路追到後端與資料庫。以檔案、函式與版本作依據，區分原始碼可證明的設計、文件描述，以及教學推演。

先跑通原始專案的最小功能，再在獨立練習專案重建選定功能。建立單機基線後，依可重現的需求或故障逐步補上分頁、索引、快取、背景任務、檔案儲存、交易與一致性、權限、觀測、擴充和部署。每個元件先說明解決的問題、成本和何時需要，並用測試或量測驗證。

Agent協作延續既有方法，研究角色追程式與文件，實作角色完成有限任務，審查角色檢查證據，由使用者主導取捨。結業成果包含固定版本的來源對照、架構圖、一條可運作的完整功能、失敗情境與設計說明。採用元件或原始碼時保留適用授權要求，避免將可讀程式與實際大規模正式環境混為同一種證據。

## 課堂節奏與共同字彙

每個教學單位約 2 小時，依目標調整。

1. 10 分鐘確認上一項證據與本堂目標。
2. 20 分鐘概念與 3～5 個必要術語，用 gallery、react-flow 或記帳的情境解釋。
3. 60 分鐘由使用者實作。主教練提供設計、線索和回饋，依需要查文件。
4. 20 分鐘驗證正常路徑與一個有意義的失敗情境，要求解釋設計。
5. 10 分鐘更新進度、問題及下一堂入口。

首次出現的縮寫附英文全名與中文意涵。術語以使用者自己的例子記錄，下一次實作、之後的整合及延後複驗時再出現。概念講解可應使用者需求先行，但每次回到當堂交付和下一個操作。

能阻礙當堂操作的問題當場解決。其他支線短答後寫入待議清單，當堂支線以 10～15 分鐘為界。環境故障約 20 分鐘仍無進展就切換預先驗證的替代方案或轉用緩衝。使用者可明確要求深入，主教練同步說明會移動的課程項目。

使用者於2026-11-09更新偏好，由主教練或開發agent直接修改課程專案，提供before／after、變更理由與實測結果。以快速建立概念和審查差異為主，手動輸入程式依使用者當堂意願安排。使用者仍參與需求與設計決策，解釋關鍵行為並檢查證據。需要觀察使用者操作時，主教練可按需讀取VS Code當下終端機結果，環境或權限變動時再選擇最少負擔的證據方式。

## Agent協作開發主線

先熟悉單一agent的需求、實作、審查、驗證與交接，再於可獨立拆分的工作練多代理協作。第一次學資料庫、交易或權限時，由使用者作設計與關鍵實作，agent提供研究、診斷或測試協助。理解後再委派相似任務，使用者仍須閱讀修改並驗證結果。

| 週 | 專項時數 | 協作練習與證據 |
|---|---:|---|
| W1 | 0.5 | 為PostgreSQL連線任務寫背景、範圍、前置條件與可觀察的完成條件 |
| W2 | 0.5 | 請agent提出測試方案與有限修改，審查差異並保留實測結果 |
| W3 | 1 | 委派一個權限相關任務，使用者用A／B使用者測試反查agent結論 |
| W4 | 1 | 用失敗注入與併發測試審查交易實作，保留一份發現與修正紀錄 |
| W5 | 1 | 讓agent準備建置或部署變更，檢查設定、秘密邊界、費用與回復方案 |
| W6 | 1 | 交付去敏感的故障證據，要求假設與查證步驟，使用者驗證根因和修正 |
| W7 | 0.5 | 將新需求拆成互相獨立的研究／實作／審查工作，練角色交接與整合 |
| W8 | 0.5 | 由使用者主導一次agent協作交付，說明決策、變更、證據與殘餘風險 |
| 合計 | 6 | 分布在既有後端任務內，總課程仍為240小時 |

六小時從原先W6產品AI選修重新分配，各週後端總額維持原表。W1～W5、W7～W8相應減少重複示範與教練代做，W6騰出時間做觀測、復原及核心補強。日常使用agent的操作時間歸屬正在完成的開發任務，專項時數只登錄明確的協作訓練，兩者不重複加總。

協作驗收要能提出可執行任務、提供必要背景、評估計畫、閱讀修改差異、驗證成功與失敗路徑，並解釋留下或修改agent建議的理由。保留任務說明、交接、程式版本、測試結果與至少一次有證據的修正紀錄。學員L3／L4可使用工具，但主教練不提供逐行解法，使用者須能現場調整需求及解釋結果。AZ-104限時評估另依正式考試允許的資源規則進行。

目前已依使用者指示建立兩個子代理完成這次規劃。子代理按任務啟動。後續啟動時把本目錄文件作為交接依據，持續研究或排程另依使用者指示安排。

每週開始前，主教練從進度表取缺口，研究者產出備課資料，審核者檢查前置條件與驗收。每週結束由主教練彙整證據，審核者判斷是否達週門檻，再回寫課綱或排補課。

## 實驗準備與資料安全

- Azure 實驗先查當期訂閱、區域、可用規格與配額，再決定網路位置。估算運算、磁碟與其他服務費，說明預計存續時間，才建立資源。
- 一次完整安排建立、實際服務測試、觀測及清理。規則模擬和真正端到端連線分開驗收，資源保留到驗證完成。
- 課程中由使用者建立計費資源，費用上限與實驗前置檢查一起記錄。備援區域與低成本替代方案先備妥。
- 不把正式系統資料、憑證或工作專案內容送到模型作為課程測資。測試、AI 和範例使用合成資料。
- 正式考試資訊在報考前重新查證，任何官方版本差異都記在來源檔。

## 全端結業門檻

下列七項全部有實際證據，才記為全端專案能力通過。日常可以查官方文件和使用 AI 工具，使用者仍須能解釋修改、執行驗證並排錯。

## AZ-104 報考評估

- 以當期官方考綱逐細項追蹤。所有細項至少能解釋或演練，每個領域都有代表實驗，實驗保留建立、驗證與清理證據。
- 抽樣獨立完成角色權限、儲存存取、部署運算、跨網路連線與監控復原的情境。至少一次真正服務連線測試。
- 使用合法且未見過的限時綜合題組做兩次練習，課內建議門檻均達 80%，各主要領域至少 70%。小樣本領域改用實驗與補充題複驗。這些是課內報考決策標準，不等於官方 700 分的換算，也不保證通過。
- 對錯題能說明原因、辨認相近設定，並用文件或實驗驗證。重做熟題分數記為複習。
- 完成官方考試介面體驗、所選考試語言的限時閱讀，以及報考當下規則查核。
