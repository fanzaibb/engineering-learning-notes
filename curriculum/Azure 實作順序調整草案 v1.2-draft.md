## 3. 週次細表

### W1 剩餘（11/10–11/11）

開工前置，不產生新的計費資源。

- 確認並清理 Day 05 的 Policy：訂閱層指派 `day05-require-env` 與 `rg-policy-day05`。**未清理前，任何缺 `env` 標籤的資源群組都會建立失敗**，之後所有實驗的資源群組都要帶 `env=Test`，或先移除指派。
- 到 Cost Management 記下剩餘額度、到期日。
- 建立預算告警（建議 50%、80%）。預算只通知，不會自動停止資源。
- 查詢配額與區域限制（vCPU、可用規格），結果記入進度檔。
- 補 Day 03 筆記（NSG 實驗記錄，來源：終端機歷史）。

### W2（11/12–11/18）Azure 10 小時：虛擬機器

對應覆蓋清單：A09、A10。

- 建立一台 Linux VM 作為 W2～W3 的共用實驗機，不用時解除配置。
- 規格調整、磁碟（新增、擴充）、可用區與可用性設定組的差異、擴展集概念與小型示範。
- VM 主機端加密（2026-04-17 考綱新增）。
- 移動資源（資源群組、訂閱、區域的限制）。

成本重點：公用 IP 與磁碟在 VM 解除配置後仍可能計費，結束時確認。

### W3（11/19–11/25）Azure 11 小時：網路、備份、監控

## 4. 預算控制規則

1. 建立任何計費資源前，先用定價計算器（TWD、實際區域）估**上限**，並寫下預計存續時間。
2. 每次實驗結束刪除整個資源群組，再以 `az group list` 確認。
3. 資源群組一律帶 `env` 標籤；建議再加 `expires` 標籤作清理提醒。
4. 每天看一次 Cost Management。

## 5. 12/5 之後的選項

由使用者決定，本草案不代為選擇：

- **升級隨用隨付**：保留資源，並繼續取得免費額度內的服務（部分服務僅 12 個月）。超出的部分向信用卡計費，須靠預算告警與每次清理控制。提早升級不損失剩餘額度。
- **不升級**：訂閱停用，已部署服務下線，不扣款，30 天內升級可恢復。選此路線，12/5 前必須把設定存成範本或指令。

加進 v1.3 的 Linux 項目（可直接貼給 ChatGPT）

位置：W2 的 VM 實驗內，不另開單元。
時數：約 3 小時，用每週餘裕吸收，不動原本的 Azure 10 小時。
練習內容（在 Azure Linux VM 上做）：

SSH（Secure Shell，安全殼層）金鑰登入，說明為什麼不用密碼。
使用者與權限：sudo、chmod、chown，看懂 rwx 與擁有者。
套件安裝與更新。
把你的後端放上 VM 並用 systemd（系統與服務管理器）管成服務：start、stop、enable、status，重開機後仍自動啟動。
日誌：journalctl、/var/log，故意設定錯誤，從日誌診斷原因。
行程與埠：ss 或 lsof 確認服務監聽哪個位址與埠。
磁碟與資源：df、du、top。
區分 NSG 與作業系統內防火牆（如 ufw）是兩層，分別擋住時的現象不同。

驗收證據（命令與輸出）：後端以服務形式在 VM 上執行並可由允許的來源連到；被 NSG 擋時呈現逾時；服務停止時呈現連線被拒絕；至少一次從日誌找出故意造成的設定錯誤。

這個練習剛好補上 Day 03 缺的那一塊：Day 03 只做了規則模擬，沒有真實監聽服務，這個項目完成後，W3 網路實驗就能直接拿它做真實連線測試。

週末版本：VM 要計費，所以放平日。如果想在週末預習，可以用 OrbStack 開本機 Linux 環境練習 1 到 3、5 到 7（請先確認你的版本支援，我沒有查），這些不花錢。

縮寫：SSH（Secure Shell，安全殼層）、rwx（read, write, execute，讀、寫、執行）、NSG（Network Security Group，網路安全性群組）。
