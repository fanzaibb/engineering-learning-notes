# 知識山域 開發指引（給 Claude Code）

版本 v0.1｜2026-11-10（Asia/Taipei）｜由 Claude 在對話中擬定，待使用者審閱。設計參考：「知識山域 v2 後端開發山」畫布。

## 0. 直接貼給 Claude Code 的開場說明

> 請閱讀 `docs/knowledge-site-guide.md`（本文件）。這是一個個人學習筆記網站，把以日期記錄的筆記改為依知識點組織。先完成第 6 節的 M1，不要一次做完所有里程碑。每個里程碑結束時停下來，給我 before／after、變更理由與實測結果，等我確認再繼續。不要修改 `curriculum/PROGRESS.md`，不要編造證據編號；資料不足的地方寫 `TODO` 並列在回報裡。所有顯示文字用台灣繁體中文，縮寫第一次出現附英文全名與中文意思。

使用前請把本文件匯出成 Markdown，放進倉庫的 `docs/knowledge-site-guide.md`。

## 1. 目標與非目標

**要解決的問題**：現行筆記以日期分檔（`notes/day-01.md` 等），同一個概念散在好幾天，幾週後回頭看不懂。

**目標**

1. 每個知識點一頁：先一句話結論，再說明、易混淆點、縮寫全名、證據與來源。
2. 知識點依「依賴順序」分層，基礎在下、進階在上，做成山形地圖。
3. 狀態與 `PROGRESS.md` 的能力等級一致：帶做＝L2、討論＝L1、待探索＝L0。
4. 每日筆記保留，但概念一律連到知識點頁。
5. **只維護 Markdown**：網站內容全部由檔案產生，不在網站裡另存一份。

**非目標（這一版不做）**

- 帳號、雲端同步、後台編輯介面。
- 自動判斷學習狀態。狀態一律由人在檔案裡寫。
- 多益山的內容。側欄保留入口即可。

## 2. 技術建議

以下是建議，Claude Code 開工前請依當時的套件版本確認可行，若有更合適的做法，先提出理由再改。

- **Vite + Vue 3 + TypeScript**：使用者熟悉 Vue，不增加新框架的學習成本。
- **內容讀取**：建置時用 Vite 的 `import.meta.glob` 以原始文字載入 `knowledge/**/*.md`，前置資料（frontmatter）用 YAML 解析，本文用 Markdown 轉 HTML 的套件。具體 API 寫法以 Vite 當期文件為準。
- **路由**：Vue Router，路徑 `/m/:mountain`、`/k/:id`、`/day/:date`。
- **位置**：放在 `engineering-learning-notes` 倉庫的 `site/` 目錄；內容放倉庫根目錄的 `knowledge/`，與 `notes/`、`curriculum/` 並列。
- **部署**：預設 GitHub Pages。也可以當 Azure 練習改用 Azure Static Web Apps，但費用與免費額度要先查官方頁面，並注意 12/5 額度到期。
- **公開注意**：倉庫目前是 public，網站內容也會公開。知識點檔案不得出現訂閱 ID、資源識別碼、金鑰、連線字串或個人資料。

## 3. 內容模型（最重要的一節）

### 3.1 檔案位置

```
knowledge/
  glossary.yml              # 縮寫對照表
  backend/
    _mountain.yml           # 這座山的分層定義
    be-01-ipv4-cidr.md
    be-02-routing.md
    ...
  azure/
    _mountain.yml
    az-01-....md
notes/
  day-01.md                 # 既有每日筆記，補上 topics 欄位
```

### 3.2 山的分層 `_mountain.yml`

```yaml
id: backend
title: 後端開發山
subtitle: 請求、資料與服務的內在邏輯
layers:                      # 由下往上，n 越小越基礎
  - { n: 1, alt: 山腳, name: 網路地基, weeks: W1 }
  - { n: 2, alt: 林道, name: 執行環境與 HTTP, weeks: W1–W2 }
  - { n: 3, alt: 溪谷, name: 資料層, weeks: W1–W2 }
  - { n: 4, alt: 稜線, name: API 契約與測試, weeks: W1–W2 }
  - { n: 5, alt: 雲霧帶, name: 身分與資料權限, weeks: W3 }
  - { n: 6, alt: 雲霧帶, name: 一致性與併發, weeks: W4 }
  - { n: 7, alt: 高原, name: 交付與維運, weeks: W4–W6 }
  - { n: 8, alt: 山頂, name: 獨立交付, weeks: W7–W8 }
mistFromLayer: 5             # 從第 5 層起以雲霧樣式呈現
```

### 3.3 知識點檔案

檔名 `<id>-<英文短名>.md`，前置資料欄位如下：

```yaml
---
id: be-08
title: HTTP 請求與回應
mountain: backend
layer: 2
status: guided            # guided | discussed | unexplored
summary: 狀態碼、標頭、本文各有分工；204 沒有本文，不能直接解析 JSON。
evidence: [E04]           # 只能填 PROGRESS.md 裡存在的編號，沒有就留空陣列
evidenceNote: 201／204／404 已驗證
weeks: [W1]
related: [be-04, be-17]
abbr: [HTTP]              # 本頁出現的縮寫，對應 glossary.yml
sources:
  - title: MDN HTTP 概觀
    url: https://developer.mozilla.org/zh-TW/docs/Web/HTTP/Overview
    kind: official        # official 官方行為 | engineering 工程取捨 | course 課程自訂
updated: 2026-11-10
---
```

本文固定段落順序（沒有內容的段落可省略，但不可改順序）：

```markdown
## 說明
## 易混淆點
## 我做過什麼
## 還沒做的
```

規則：

- `summary` 一句話，不超過 60 字，不放但書。限制寫在「易混淆點」。
- 「我做過什麼」只能寫有證據的內容，並標出證據編號；教練代做的寫明「帶做」。
- 來源 `kind` 必填，因為使用者要求區分官方行為、工程取捨與課程自訂慣例。

### 3.4 縮寫表 `glossary.yml`

```yaml
- abbr: CORS
  full: Cross-Origin Resource Sharing
  zh: 跨來源資源共享
- abbr: NSG
  full: Network Security Group
  zh: 網路安全性群組
```

縮寫在網站上的呈現方式如下，知識點頁與每日頁都適用：

1. **每一次出現都可以 hover 看全文**：渲染本文時，把 `glossary.yml` 裡有的縮寫包成縮寫元件，滑鼠移上去出現 tooltip，內容為「Cross-Origin Resource Sharing，跨來源資源共享」。
2. **鍵盤與手機也要能看**：元件可用 Tab 聚焦，聚焦時同樣顯示 tooltip；手機上點一下顯示、再點一下或點空白處關閉。只用 HTML 的 `title` 屬性不夠，因為觸控與鍵盤看不到，需自製 tooltip，並用 `aria-describedby` 讓螢幕閱讀器讀得到。
3. **第一次出現另外寫出全名**：每頁第一次出現時仍顯示「CORS（Cross-Origin Resource Sharing，跨來源資源共享）」，之後只顯示縮寫加 tooltip。
4. **比對規則**：整個詞比對、區分大小寫（避免把 IP 套到 ZIP 裡）；程式碼區塊、行內程式碼與連結文字內不套用。
5. **檢查**：`npm run check` 掃描本文中連續 2 個以上大寫字母的詞，不在 `glossary.yml` 的列成警告，提醒補表（警告不中止建置）。

### 3.5 每日筆記

既有 `notes/day-xx.md` 不改內容，只在檔案開頭加上：

```yaml
---
date: 2026-11-05
topics: [be-02, be-04, be-07, be-08]
---
```

網站在知識點頁顯示「出現在 Day 01、Day 04」，在每日頁顯示該日的知識點清單。

## 4. 頁面與功能

### 4.1 山域地圖（首頁）

- 每層一條水平帶，由下往上排列，帶的左側顯示層名與週次。越上層，左右內縮越多，形成山形。
- 第 5 層以上套用雲霧樣式（半透明白色帶）。
- **不畫知識點之間的連線**。相關知識點只在選取後的詳細區顯示，避免數量多時交錯成一團。
- 狀態不能只靠顏色區分：帶做是實心點加實線框，討論是空心點加實線框，待探索是虛線框加虛線點。
- 點選知識點後，下方顯示一句話結論、狀態、層級、證據、週次、相關知識點，以及前往完整頁的連結。
- 頁尾固定說明：位置代表依賴順序，不代表完成率。

### 4.2 清單檢視

- 與地圖超過 30 個時，切換，由第 1 層往上列出，每列顯示名稱、狀態、一句話結論、證據。
- 知識點清單是主要入口，地圖是輔助。

### 4.3 篩選與搜尋

- 狀態篩選：全部、帶做、討論、待探索，並顯示數量。
- 搜尋比對標題與一句話結論。地圖上不符合的知識點變淡，不移除，維持位置。

### 4.4 知識點頁 `/k/:id`

- 頁首：標題、狀態、所在山與層、一句話結論（最大字級）。
- 本文依 3.3 的段落順序。
- 側欄：證據、週次、相關知識點、出現在哪幾天、縮寫、來源（依 kind 分組）。

### 4.5 每日頁 `/day/:date`

- 顯示原始每日筆記，頁首列出當天的知識點連結。

### 4.6 共通要求

- 手機寬度可用：側欄堆疊到上方，地圖帶寬自動換行，不產生水平捲動。
- 可點擊的元素用真正的 `button` 或 `a`，觸控區至少 44px，文字對比至少 4.5:1。
- 收藏或最近瀏覽若存在瀏覽器（localStorage），讀寫要包 try/catch，並在頁尾說明只存在這台裝置。

## 5. 內容檢查腳本 `npm run check`

建置前必跑，失敗就中止：

1. 必填欄位：`id`、`title`、`mountain`、`layer`、`status`、`summary`、`updated`。
2. `id` 不重複，且與檔名前綴一致。
3. `layer` 存在於該山的 `_mountain.yml`。
4. `status` 只能是三個值之一。
5. `related` 指向的 id 都存在。
6. **`evidence` 的每個編號都能在 `curriculum/PROGRESS.md` 的證據索引表找到**（以 `| E<數字> |` 開頭的列）。找不到就失敗，避免網站出現編造的證據。
7. `abbr` 的每個縮寫都在 `glossary.yml`。
8. `notes/*.md` 的 `topics` 指向的 id 都存在。
9. 敏感資訊掃描：出現 GUID 格式、`/subscriptions/`、`AccountKey=`、`password` 等字樣時警告。

## 8. 給 Claude Code 的工作規則

1. 一次只做一個里程碑，結束時回報：做了什麼、before／after、為什麼這樣做、怎麼驗證、還剩什麼 TODO。
2. 不修改 `curriculum/` 下的任何檔案；需要更新進度時，把建議的文字放在回報裡，由使用者決定。
3. 不編造證據、日期或來源。從筆記整理內容時，只寫筆記裡有的；推論要標「整理者補充」。
4. 來源依官方行為、工程取捨、課程自訂三類標示。
5. 新增套件前說明用途與替代方案，優先用已有的工具。
6. 不提交 `.env`、金鑰或任何雲端資源識別碼；倉庫是 public。
7. 使用者偏好：先建立概念、再看差異；手動輸入程式依使用者當時意願，不預設要他自己寫。

## 8.5 課後擴增知識庫的流程（多個 agent 共用）

每次課程結束，不論是 ChatGPT、Claude 或 Claude Code 上的課，都照同一份流程把內容併進知識庫。規則寫在倉庫的 `knowledge/CONTRIBUTING.md`，每個 agent 上課前先讀它；Claude Code 在 M7 建立這份檔案。

**權責：誰能改什麼**

| 檔案 | 誰寫 | 規則 |
| --- | --- | --- |
| `curriculum/PROGRESS.md` | 當堂授課的 agent 提案、使用者確認 | 唯一的進度與證據來源；同一時間只有一邊寫 |
| `notes/day-xx.md` | 當堂授課的 agent | 每堂一份，記做了什麼與證據 |
| `knowledge/**/*.md` | 有倉庫寫入權的 agent（Claude Code），或使用者照交接包貼上 | 只能追加，不刪別人寫的內容 |
| `knowledge/glossary.yml` | 同上 | 新縮寫一律補表 |

**課後五步**

1. **寫每日筆記**：授課的 agent 產出 `notes/day-xx.md`，前置資料加上 `date`、`agent`（chatgpt、claude、claude-code）、`topics`（本堂碰到的知識點 id）。
2. **產出交接包**：同一個 agent 依 `knowledge/_templates/session-patch.md` 的固定格式，列出三類變更。一是既有知識點要追加的內容（寫到哪個檔、哪個段落）；二是新知識點（建議 id、層、一句話結論、狀態）；三是新縮寫。每段追加文字開頭標「（2026-11-11，Claude）」這樣的日期與來源。
3. **使用者確認**：看過交接包再放行。狀態要升級（例如討論→帶做），必須先在 PROGRESS.md 有對應的證據編號。
4. **套用與檢查**：有倉庫權限的 agent 依交接包修改檔案並執行 `npm run check`；聊天介面裡的 agent 沒有權限時，交接包就是可直接貼進檔案的完整內容，由使用者貼上或轉給 Claude Code。
5. **提交**：一堂課一個 commit，訊息格式 `knowledge: day-xx（agent）`，方便之後追查是誰、哪一堂加的。

**拿不準的內容先放收件匣**：不確定該歸哪個知識點、或跟既有說法衝突時，寫進 `knowledge/_inbox/2026-11-11-claude.md`，不直接改正式檔。檢查腳本會列出收件匣裡尚未處理的檔案，提醒使用者整理。

**兩個 agent 說法不同時**：不覆蓋，把兩種說法都寫進該知識點的「易混淆點」，各自標來源，並列進交接包的「待使用者裁決」。以官方文件為準時，附上連結與查證日期。

**檢查腳本補充規則**（併入第 5 節）：

- 每份 `notes/*.md` 必須有 `agent` 欄位。
- 知識點的新 id 依序編號、不重複、不重用已刪除的號碼。
- `_inbox/` 有檔案時顯示警告，不中止建置。

**里程碑補充**：M7 擴增流程——建立 `knowledge/CONTRIBUTING.md`、交接包範本與收件匣檢查；完成條件是拿 Day 05 筆記模擬一次課後流程，產出交接包、套用後 `npm run check` 通過。
