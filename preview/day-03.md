# Day 03｜Azure 網路規則驗證

2026-11-07 · 第一週 · 帶做／規則模擬

**今天驗證了兩個來源會命中哪條規則。下一次要讓服務真的接收請求，觀察連線結果。**

## 先看懂規則

**NSG（Network Security Group，網路安全性群組）會按優先順序判斷流量，數字越小越早檢查。**

在東亞的資料庫子網路 `10.0.1.128/25` 掛上 `nsg-day03-db`。目的地是虛擬機器 `vm-day03-db` 的 `10.0.1.150:5432`，入站使用 TCP（Transmission Control Protocol，傳輸控制協定）。

| 優先順序 | 來源 | 結果 |
|---|---|---|
| 100 | 應用子網路 `10.0.1.0/25` | Allow |
| 200 | 任意其他來源 | Deny |

## 看當天的證據

用 `az network watcher test-ip-flow` 檢查入站規則。指令歷史留下的來源是 `10.0.1.22` 與 `10.0.1.130`，預期分別為允許與拒絕。當日回報符合預期，原始輸出未保存。實驗後回報兩個練習資源群組均已清理。

**重做時選可分配的來源位址。** `10.0.1.130` 是 Azure 保留位址。規則模擬可改用 `10.0.1.132`，真實連線則用測試機實際分配到的位址。當天的虛擬機器沒有在 5432 啟動監聽服務。

## 下次怎麼驗證

先讓記帳服務在虛擬機器上監聽，再用允許的來源送一個新請求。接著在同一套環境中各改一項條件，重測規則拒絕與服務停止。把實際錯誤訊息、監聽狀態和命中規則一起記下，區分規則判斷與連線證據。
